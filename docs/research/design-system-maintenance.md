# Design system maintenance practices

Status: **research**, 2026-11-24. Nothing is decided. This note compares published practice with this repository and proposes ten changes. It changes no code.

## Summary

1. The repository already does the hard parts: owned shadcn source with a three-way merge base, a closed API that the packed-package test checks, one variant vocabulary, stories that run as tests in two themes with axe set to fail, and measured glass contrast.
2. The gates do not see pixels. There is no screenshot baseline, the glass contrast and edge scripts only print, and nothing measures non-text contrast (control boundaries, focus rings).
3. Change management is informal. No document defines a breaking change for tokens and CSS, nothing is deprecated before removal, and no codemod or component status exists.
4. Upstream drift is found only when a person runs `pnpm shadcn:update --check`. No schedule and no dependency bot exist in the repository.
5. Nothing in this repository measures adoption or drift in Echopoint and Anchor. First steps: gate glass contrast in CI, snapshot the token set, and write a versioning and deprecation policy.

## Prioritised recommendations

Order: value per effort, highest first. Each item is one focused PR. Items 3 and 4 change process documents, so they need Alexis's agreement first.

1. **Gate glass text contrast in CI (M).** In `scripts/measure-glass-contrast.mjs`, add `--min 4.5`. Set `process.exitCode = 1` when muted or primary text is below the minimum or, after one clean run confirms that no surface is missing today, when a surface is `MISSING`. Let the script serve the built `site/` on an ephemeral port, as `scripts/test-motion.mjs` does, so it needs no running Storybook. Add a `glassContrast` check to `.dagger/modules/designsystem/main.dang` after the Storybook build, and add it to the `storybook-motion` matrix entry in `.github/workflows/ci.yml`. Keep `measure-glass-edge.mjs` as a report: its targets are design choices, not WCAG limits.
2. **Snapshot the token set (S).** Add `scripts/check-tokens.mjs`. It parses the `:root` and `.dark` blocks of `src/styles.css`, writes the sorted token names to a committed `tokens.lock.json`, and fails when a name disappears, or when a colour token in `:root` has no `.dark` value and is not on an allow list. A removal must update the lock file in the same PR as its CHANGELOG line. Run it from `pnpm lint` in `package.json`, so the existing `lint` check covers it.
3. **Write the versioning and deprecation policy (S, then M).** Add `docs/technical/versioning.md`. List the public surface: package export paths, component and prop names, prop values, token names, documented product hooks such as `--app-shell-brand-tile`, and `data-ns-material`. In 0.x, a minor may break and needs an `Upgrade:` line; a patch must not remove or rename anything (0.3.1 did). Before removal, deprecate for at least one minor: JSDoc `@deprecated Use X` on the prop or export, a dev-only warn-once helper in `src/lib/deprecate.ts`, the Storybook tag `deprecated`, a `Deprecated:` CHANGELOG line, and for a token an alias (`--old: var(--new)`) with a removal version. A prop rename ships a transform in `scripts/codemods/<version>/`, linked from the `Upgrade:` line. State the 1.0 criteria. Link the page from the AGENTS.md Release section and `docs/README.md`.
4. **Add screenshot baselines (L, start with a spike).** Add a Vitest project `visual` in `vitest.config.ts` that runs only stories tagged `visual` and calls `toMatchScreenshot` on the story root after play. Tag the glass stories, the `WorstCase` stories and one default story per component, in both themes. Render and update baselines only in the Dagger Playwright image (`dagger.toml` `playwrightImage`), through a manually dispatched workflow, never on a laptop. Add a `visual` Dagger check and CI matrix entry. AGENTS.md now says screenshots never go in a commit, so committed baselines need an explicit exception in its Gates section. Chromatic is the hosted option; it keeps baselines out of Git but is an external service.
5. **Check non-text contrast from tokens (S).** Add `scripts/check-contrast.mjs` (or extend item 2). Resolve opaque `hsl()` tokens for both themes and assert: text pairs (`--foreground` and each `*-foreground` on its surface, each `*-on-tint` on its tint) at 4.5:1; `--ring` against `--background`, `--card` and `--popover` at 3:1; `--input` and `--border-strong` at 3:1 against their surface where that line is the only boundary of an unfilled control. Skip alpha tokens, which item 1 covers. Record the pair list and results in `docs/technical/material.md` or a new accessibility page.
6. **Schedule the upstream drift check (S).** In `scripts/shadcn-update.mjs`, make `--check` exit 2 when a component changed (now 0) and print a summary line. Add `.github/workflows/upstream-drift.yml`: weekly `schedule` and `workflow_dispatch`, `permissions: issues: write`, `pnpm install`, then `pnpm shadcn:update --check`. On exit 2, create or update one issue titled "shadcn upstream changed" with the list. Add `renovate.json` with groups for `@base-ui/react`, `shadcn`, Storybook and Vitest, and Tailwind, unless an org-level config already covers this repository.
7. **Verify releases with the CI checks (M).** In `.github/workflows/release.yml`, replace the `pnpm lint` to `pnpm test:motion` steps of the `verify` job with the `setup-dagger` action and `dagger check`. Keep the identity and changelog steps, and keep `pnpm install` and `pnpm build` before the pack step: `npm pack --ignore-scripts` needs `dist` on the runner. Better, export `dist` from the Dagger `package` check and pack that, so the packed output is the tested one, as `docs/runbooks/deployment.md` promises. The release then verifies in the same pinned image as CI, and the `ubuntu-24.04` pin for Playwright can go.
8. **Report consumer adoption and drift (M).** Add `scripts/usage-report.mjs` with `react-scanner` as a dev dependency. Input: paths to Echopoint and Anchor checkouts. Output a Markdown table: uses per component, `Box` uses with `className`, imports not from `@nanostackorg/design-system`, files under any `components/ui/`, palette or arbitrary colour classes, and the installed version against `package.json` `version`. Run it monthly and before a breaking release, to size the migration. Keep the output out of the repository unless a decision needs it.
9. **Lint stories and show component status (S).** Add `scripts/check-stories.mjs` to `pnpm lint`. Fail when a directory in `src/components/` or `src/blocks/` has no story, or when its story has no `docs.description.component` with a "Do not" list (fix `text` and `text-link` first). Print, but do not fail on, the components with no `WorstCase` story. Add Storybook `tags` `experimental` and `deprecated` and list them in a status table in `docs/technical/architecture.md`.
10. **Add request and PR templates (S).** Add `.github/ISSUE_TEMPLATE/variant-request.yml` and `component-request.yml`. Their fields follow ADR 0001 "Where a new component goes": the two product uses, the component tried first, screenshots, and why a product component does not fit. Add `.github/pull_request_template.md` with the Gates, rule 11 findings, the CHANGELOG and `Upgrade:` line, deprecations, and before/after evidence.

Not recommended now: Changesets (one package; `release.yml` already enforces the changelog), components through a shadcn registry (row 21), renamed token tiers (rule 6), and Chromatic as the first choice (an external service; item 4 uses the pinned Dagger image instead).
